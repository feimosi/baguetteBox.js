# Migration Plan

## Working Agreement
- Execute exactly one migration phase at a time.
- Stop after each phase and wait for explicit approval before starting the next one.
- Create one git commit per phase.
- Preserve the public API and flat `dist` artifact names unless a later approved phase explicitly changes that contract.

## Goal
- Migrate the library source from JavaScript to strict TypeScript and resolve all type errors.
- Modernize build tooling with a recommendation grounded in this repo's actual needs.
- Replace Sass if it no longer provides enough value, while keeping styles stable.
- Upgrade dependencies selectively based on risk and payoff.
- Add UI smoke tests to protect the migration.

## Current State Assessment
- Runtime source is concentrated in `src/baguetteBox.js`, a single UMD-style library file with a small public API: `run`, `show`, `showNext`, `showPrevious`, `hide`, and `destroy`.
- Styles are concentrated in `src/baguetteBox.scss` and use only light Sass features: nesting, `&`, one placeholder selector, and `@extend`.
- Build and release logic are concentrated in `gulpfile.js` and `package.json`.
- The current build pipeline:
  - compiles Sass
  - concatenates source files
  - minifies JS and CSS into `dist`
  - injects the package version into banners
  - serves the demo via BrowserSync
  - handles version bump and demo deployment tasks
- There is no automated browser test suite today. Current `test` is effectively build plus lint.
- The repo still documents a very old browser support matrix, but the agreed migration posture is balanced:
  - keep the public API and output contract stable
  - allow removal of clearly obsolete browser-only code when it blocks strict typing or tool modernization

## Recommendations

### Build Tooling
- Recommendation: keep Gulp, but upgrade and simplify it instead of moving to Vite.
- Rationale:
  - This project is a small published library, not an application.
  - Its build needs are simple artifact assembly, not a modern app bundler pipeline.
  - Vite would add configuration complexity to preserve the current output names, global/UMD behavior, and release flow.
  - TypeScript can be introduced cleanly without replacing Gulp.

### CSS
- Recommendation: migrate from Sass to plain CSS.
- Rationale:
  - The current Sass usage is minimal and does not justify keeping a preprocessor.
  - The stylesheet can be flattened with low risk while preserving selectors and behavior.

### TypeScript
- Recommendation: migrate the runtime source to strict TypeScript in one dedicated phase.
- Rationale:
  - The source surface is small enough to migrate methodically.
  - Strict typing will surface hidden contract issues early.
  - The migration should preserve runtime behavior and artifact names.

### UI Testing
- Recommendation: add Playwright smoke tests against the demo page.
- Rationale:
  - Browser-level coverage is the best fit for this library.
  - A small smoke suite will catch regressions after each migration phase.

## Phase 0
### Purpose
- Establish the approved migration baseline before functional changes begin.

### Deliverables
- Create this in-repo migration plan at `.migration-plan.md`.
- Record the accepted compatibility posture and migration rules.
- Define success criteria and execution order for later phases.
- Create a dedicated branch for the migration work: `baguetteBox-next`.

### Success Criteria
- The branch exists.
- `.migration-plan.md` is committed.
- The plan reflects the agreed phase-by-phase workflow and balanced compatibility target.

### Risks
- Starting implementation without a committed baseline can blur scope and make later decisions harder to audit.

## Phase 1
### Purpose
- Add a regression safety net before build, CSS, and TypeScript refactors.

### Proposed Changes
- Add Playwright.
- Add a lightweight local test harness for the demo page.
- Add smoke coverage for:
  - opening and closing the overlay
  - keyboard and button navigation
  - captions and callback-driven caption behavior
  - responsive image source selection
  - config variants such as `fadeIn`, `noScrollbars`, and `buttons: false`
- Add a very small set of deterministic screenshot baselines before CSS work begins:
  - overlay open, with the visual state settled
  - overlay after navigating to the second image
  - keep any closed-state check lightweight and only snapshot it if it meaningfully protects page-state regressions

### Verification
- Smoke tests pass against the pre-migration behavior.
- Visual snapshot tests pass against the pre-CSS baseline.
- The suite is fast enough to run after every later phase.

### Risks
- Flaky async assertions around image loading or transitions.

## Phase 2
### Purpose
- Add GitHub CI coverage for the new Playwright UI tests before larger migration work begins.

### Proposed Changes
- Add a GitHub Actions workflow that runs on `push` and `pull_request`.
- Use a macOS runner so the screenshot baseline stays aligned with the current macOS-only snapshot assumption.
- Install Node.js, dependencies, and a known Chrome binary path for the Playwright config.
- Run `npm run test:ui` in CI and fail the workflow if the smoke or snapshot checks regress.

### Verification
- The workflow is present in `.github/workflows/`.
- The workflow command matches the documented local command.
- The Playwright config can resolve Chrome both locally and in CI.

### Risks
- Snapshot tests can be sensitive to browser-version drift, especially when CI and local Chrome versions differ.

## Phase 3
### Purpose
- Modernize the build pipeline without changing the published artifact contract.

### Proposed Changes
- Upgrade from Gulp 3 task syntax to Gulp 4-compatible composition.
- Remove obsolete helpers such as `run-sequence`.
- Remove the stale `postinstall` rebuild of `node-sass`.
- Reassess and, where justified, replace or remove outdated Gulp plugins.

### Verification
- `build` still produces:
  - `dist/baguetteBox.js`
  - `dist/baguetteBox.min.js`
  - `dist/baguetteBox.css`
  - `dist/baguetteBox.min.css`
- Version banner injection still works.
- Demo behavior and smoke tests remain green.

### Risks
- Plugin incompatibilities during the Gulp upgrade.
- Small output differences from updated minification tooling.

## Phase 4
### Purpose
- Replace Sass with plain CSS in isolation.

### Proposed Changes
- Convert `src/baguetteBox.scss` to equivalent plain CSS.
- Flatten nested selectors and replace placeholder/`@extend` behavior with explicit CSS selectors.
- Remove Sass from the library stylesheet build path once parity is verified.

### Verification
- Demo styling matches baseline behavior.
- Smoke tests remain green.

### Risks
- Selector specificity or declaration-order drift affecting overlay, buttons, or animations.

## Phase 5
### Purpose
- Migrate the library source to strict TypeScript.

### Proposed Changes
- Add `tsconfig.json` with strict settings.
- Rename `src/baguetteBox.js` to `src/baguetteBox.ts`.
- Add explicit types for public options, gallery state, callbacks, DOM references, and event handlers.
- Resolve type and behavior ambiguities during the migration instead of deferring them.

### Verification
- `tsc --noEmit` passes with zero errors.
- Build output names stay stable.
- Smoke tests pass.
- Manual demo sanity check still passes.

### Risks
- TypeScript may expose hidden assumptions in DOM nullability, event typing, fullscreen handling, or `show(index, gallery)` semantics.

## Phase 6
### Purpose
- Apply dependency upgrades selectively and document the new workflow.

### Proposed Changes
- Upgrade low-risk packages in small logical groups.
- Keep major upgrades tied to already-approved migration work.
- Remove dependencies that become unnecessary after earlier phases.
- Update `README.md`, `CONTRIBUTING.md`, and package scripts/metadata to match the migrated workflow.

### Verification
- Install, build, typecheck, and smoke tests all succeed.
- Documentation matches the actual commands and output layout.

### Risks
- Bundling too many upgrades into one step can hide the source of regressions.

## Dependency Upgrade Triage
- Low-risk or likely worthwhile:
  - `gulp-bump`
  - `gulp-load-plugins`
  - `jsonfile`
- Requires deliberate code or workflow changes:
  - `gulp`
  - `gulp-autoprefixer`
  - `gulp-eslint`
  - `gulp-if`
  - `gulp-sass`
- Likely removal candidates instead of direct upgrade:
  - `run-sequence`
  - stale `node-sass` rebuild step
  - Sass-related dependencies after CSS migration
  - unused Gulp plugins discovered during the pipeline rewrite

## Global Acceptance Criteria
- Each phase is independently executable and verifiable.
- No phase leaves build errors or type errors unresolved.
- No phase proceeds without explicit approval.
- Public API remains stable unless a later approved phase intentionally changes it.
- Flat `dist` output names remain stable unless a later approved phase intentionally changes them.

## Planned Execution Order
1. Phase 0: baseline, branch, and committed plan.
2. Phase 1: UI smoke tests.
3. Phase 2: GitHub CI for UI tests.
4. Phase 3: Gulp modernization.
5. Phase 4: Sass to CSS migration.
6. Phase 5: JavaScript to strict TypeScript migration.
7. Phase 6: dependency upgrades and documentation alignment.
